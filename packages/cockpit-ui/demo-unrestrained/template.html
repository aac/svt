@surface/cockpit · headless engine, off the leash

Triage Orbit

This is an ordinary five-item triage queue — but you would never know it. There is no list, no two-pane detail, no --cockpit-* token in sight. The queue is a rotating constellation; the focused item is a glowing core; deciding an item ejects it from orbit.

And yet every behaviour is the real shipped engine. Focus, wrap-around navigation, action dispatch, and the focused-item bus are all @surface/cockpit — imported, bundled, and running live below. Not one line of @surface/cockpit-ui is on this page. That is the whole demonstration: headless is not a styling knob, it is a different room you build yourself.

01 The engine, unchanged

useCockpit({ items, actions, onAction }) gives back focusedIndex, focusedItem, setFocusedItem, invokeAction. The orbit reads those to place nodes and fill the core. State and behaviour are 100% library; pixels are 100% consumer.

02 Consumer keymap

useCockpitKeys runs a custom map — arrows and W/S rotate, Enter pulses focus — over the exact resolver the shipped <Cockpit> uses. The default is j/k; keys were never baked in.

03 The same bus

The bus monitor subscribes to cockpitBus's focused-item event — the identical seam the voice library listens on to set its correlation id. Rotate the ring and watch it fire.

Why this matters. The shipped display has a paint-and-trim seam: 22 tokens re-skin the two-pane layout without touching JSX. This page shows the carpentry seam underneath it. Asked for “something even wildly different… something unrestrained,” this is the answer — a UI with no structural resemblance to the cockpit whatsoever, built on nothing but the headless contract. If styling were truly “predetermined,” Triage Orbit could not exist. It runs on the same engine that renders the default.
